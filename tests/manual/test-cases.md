# Manual Test Cases — Jira AC Assistant

## TC-1: Automatic Polling — Happy Path (High Confidence)

**Preconditions:**
- App is running with `JIRA_POLLING_ENABLED=true`
- A new Jira ticket (Story/Task) exists in IGAL project with a detailed description
- Ticket has no labels, no existing "Acceptance Criteria" section
- Ticket was created within the last 7 days

**Steps:**
1. Wait for the next poll cycle (check logs for "Poll cycle: discovered N tickets")
2. Observe the ticket being processed in the logs

**Expected Results:**
- Poller discovers the ticket
- Barley enrichment is attempted (topics extracted)
- AI generates acceptance criteria (log: "AI generated N acceptance criteria")
- Confidence score >= 0.70 — no Slack escalation triggered
- ACs are written to Jira ticket description (under "## Acceptance Criteria" heading)
- Attribution line added: "Generated by Jira AC Assistant on {date}"
- Label `ac-generated` is added to the ticket
- On subsequent poll cycles, the ticket is NOT re-processed

---

## TC-2: Automatic Polling — Low Confidence Escalation

**Preconditions:**
- App is running with polling enabled
- A new Jira ticket exists with a vague/minimal description (e.g., just a title and one sentence)
- `SLACK_ESCALATION_CONTACT_EMAIL` is configured
- `SLACK_CONFIDENCE_THRESHOLD=0.70`

**Steps:**
1. Wait for the poll cycle to process the ticket
2. Check app logs for confidence score
3. Check Slack DM for the escalation contact

**Expected Results:**
- AI generates ACs with confidence < 0.70
- Log: "Low confidence (X.XX < 0.70) for {KEY}, escalating via Slack"
- Slack DM is sent to the escalation contact with:
  - Ticket key and summary as header
  - "View in Jira" link
  - List of confidence gaps (bullet points)
  - Footer: "These draft ACs have been added to the ticket for reference."
- Draft ACs are written to Jira with note: "Note: Clarification has been requested from the Product Owner..."
- Escalation record is stored in the database (table `escalations`, status=SENT)
- Label `ac-generated` is added

## TC-8: Barley Enrichment — Timeout Fallback

2. Observe logs during Barley enrichment

**Expected Results:**
- Topics are extracted from ticket (via AI)

- ACs are still generated and written successfully

## TC-10: Manual Re-trigger via Slack DM — Full Approve Flow

**Preconditions:**
- App is running with Socket Mode enabled
- User has a DM channel with the bot

**Steps:**
1. Send a message to the bot: `IGAL-1981` (or any valid ticket key)
2. Wait for the bot to respond with AC comparison
3. Reply with: `approve`

**Expected Results:**
- Step 1: Bot acknowledges, starts processing
  - Label `regenerating` is added to ticket
  - Existing ACs are extracted from ticket
  - New ACs are generated
- Step 2: Bot sends comparison message with:
  - Ticket key
  - "Existing Acceptance Criteria" (bulleted list)
  - "Proposed New Acceptance Criteria" (bulleted list)
  - Instructions: "Reply with 'approve'..."
- Step 3: Bot responds: "Done! ACs updated on {KEY}. {JIRA_URL}"
  - New ACs replace existing ACs in Jira description
  - Label `regenerating` is removed
  - Conversation status set to COMPLETED in database

---
